Background Image Technique

Each product section uses a full-width background image combining CSS background-image with a VML v:rect fallback, ensuring correct rendering in Outlook 2013–365. Each VML block includes explicit width and height declarations matching the content height of its section.

Transparent Product Images

Fragrance bottle images use transparent WebP assets sourced from Scentbird's public CDN. A bgcolor fallback matching each section's color palette was applied to the containing <td> to handle Gmail's inconsistent WebP transparency rendering.

Bulletproof CTA Buttons

All Subscribe Now CTAs use the VML bulletproof button technique (v:rect + w:anchorlock), ensuring solid background color and correct dimensions in all Outlook versions where CSS background-color on anchor tags is not supported.

Dark Mode Handling

Dark Mode support was implemented using two complementary techniques:

  • u+.body { mix-blend-mode: screen } for Gmail Dark Mode handling
  • @media (prefers-color-scheme: dark) overrides for Apple Mail and iOS Mail

The dark header and footer sections are intentionally dark-first, eliminating color inversion issues in those areas across all clients.

Fluid Responsive Layout

Mobile responsiveness was achieved through:

  • Percentage-based widths with max-width constraints on key containers
  • display: inline-block on fragrance note icon cells for natural wrapping behavior
  • Fluid image scaling using width: 100% with max-width declarations

This approach avoids media query dependency for core stacking behavior, ensuring compatibility with Gmail mobile's limited CSS support in the <head>.

Modular Architecture

The email is structured as six independent product modules sharing identical HTML architecture. Only the following change between modules:

  • Background image URL
  • Product bottle image URL and link
  • Brand name and fragrance name
  • Fragrance note icons and labels
  • CTA destination URL

This makes the template fully scalable — new products can be added by duplicating one module block and updating its variables, with no structural changes required.

Fluid Layout Without Media Queries

The email uses percentage-based widths with max-width constraints on all key containers rather than relying on media queries for core layout behavior. This ensures the email reads correctly in Gmail mobile, which strips <head> CSS entirely. The two-column perk card layout maintains readability down to approximately 360px without any stacking logic.

Bulletproof Rounded Buttons

Primary and secondary CTAs use different VML approaches intentionally:

  • Primary CTA — v:roundrect with arcsize="8%" produces rounded corners in Outlook, matching the original's brand style
  • Secondary CTA — outline button using CSS border inline style with a v:roundrect fallback for Outlook

This demonstrates two different bulletproof button patterns within the same email — solid fill and outlined.

Preheader Padding with Invisible Characters

The preheader uses zero-width non-joiner characters (͏‌) to pad the preview text to full length. This prevents email clients from pulling in body copy as additional preview text, giving full control over the inbox preview string without adding visible content.

Dark Mode Handling

  • u+.body .txt_white { mix-blend-mode: screen } for Gmail dark mode text handling
  • @media (prefers-color-scheme: dark) overrides for Apple Mail and iOS Mail

Outlook-Safe Section Dividers

Visual dividers between sections use bgcolor on a <td> with a fixed pixel height spacer rather than CSS border or hr elements. This ensures consistent rendering across all Outlook versions, which handle CSS borders inconsistently in table-based layouts.

This email recreation is based on Headspace's "All Day, Everyday Support" engagement campaign. The build replicates the original's editorial two-column layout — a left column of stacked feature images alongside a vertical timeline graphic, paired with a right column of headline, body copy, and inline CTAs — presenting four product features in a single structured flow.

The layout uses a hide/show architecture to handle the desktop-to-mobile transition. The image column and desktop timeline are hidden on mobile via .hide, while equivalent images are re-injected inline within the text column using .show_mob. This guarantees correct render order across all clients without relying on CSS column stacking, which Gmail mobile does not support.

Special attention was given to:

  • Dual timeline image assets — separate fixed-height graphics for desktop and mobile to maintain alignment across all four article anchors
  • Custom @font-face loading of Headspace's proprietary Apercu typeface via their static CDN, with full Arial fallback chain for Outlook and Gmail
  • Comprehensive mobile spacer overrides — independent height and font-size classes for each spacer row, allowing precise layout control without duplicating structural markup
  • Bulletproof CTA buttons using v:roundrect with arcsize for correct pill-shaped rendering in all Outlook versions
  • Cross-client dark mode support via mix-blend-mode: screen for Gmail and color-scheme: light dark for client-level awareness

Hide/Show Dual-Column Architecture

The desktop layout uses a three-cell row structure: a left <td> with stacked feature images, a center <td> with the vertical timeline graphic, and a right <td> with article text. On mobile, the image column and desktop timeline are hidden via .hide { display: none !important; }, and equivalent images are re-injected inline within the text column using .show_mob { display: block !important; }. This approach avoids CSS column stacking — a technique required because Gmail mobile strips <head> CSS that would otherwise handle column reordering.

Dual Timeline Image Assets

The vertical timeline line is implemented as an <img> rather than a CSS border or background, using two separate image assets at different fixed heights — one sized for desktop spacing, one for mobile. The desktop version is hidden on mobile via .hide and the mobile version is hidden on desktop via inline display: none, revealed on mobile via .show_mob. This ensures the timeline correctly spans all four article anchors at both viewport sizes without dynamic height calculations.

Custom @font-face Loading

The email loads Headspace's proprietary Apercu-Regular and Apercu-Bold typefaces via @font-face declarations pointing to Headspace's static CDN (static.headspace.com/fonts/). All font declarations include Arial, Helvetica, sans-serif fallbacks for clients that block external font loading. MSO-specific styles force Arial across all Outlook versions to prevent font substitution issues.

Comprehensive Mobile Spacer Overrides

All vertical spacing uses explicit height spacer <td> rows with dedicated mobile override classes (.h98, .h56, .h45, etc.) that independently control height and line-height at the mobile breakpoint. Font size overrides follow the same pattern (.fs37_lh42, .fs20_lh24, etc.). This approach is more reliable than margin or padding-top in table-based layouts, particularly in Outlook where CSS box model behavior is inconsistent.

Bulletproof Pill-Shaped Buttons

CTA buttons use v:roundrect with arcsize="49%" for Outlook rendering — producing correctly pill-shaped buttons in all Outlook versions where CSS border-radius is ignored. v:rect was not used here as it produces square corners and would not match the original design.

Dark Mode Handling

Dark mode support is implemented using two complementary techniques:

  • color-scheme: light dark declared in :root for client-level color scheme awareness
  • u+.body .txt_white { mix-blend-mode: screen } for Gmail dark mode text handling
  • u+.body .txt_white2 { mix-blend-mode: difference } for secondary text elements

Social Icons — Table-Based Spacing

Social icons (Facebook, Instagram, X, YouTube) use a dedicated <table> with fixed-width spacer <td> cells between each icon — a more Outlook-consistent approach than inline &nbsp; spacing, ensuring even gaps across all clients.

Preheader Padding

The preheader uses zero-width non-joiner characters (͏‌) to pad the preview text to the desired length, preventing email clients from pulling visible body copy into the inbox preview snippet — a standard production technique used across all three portfolio emails.
